# Remesh Parity Blocker — Updated 2026-06-29 18:45Z

**Branch:** `cc/molten-remesh-parity-0629`
**Diaulos:** trellis-remesh-parity

## Current Understanding

The official TRELLIS.2 pipeline produces coherent, hole-free meshes from the T.png demo image. Our trellis2mlx pipeline produces a raw mesh with 5,652 boundary loops and 300K non-manifold edges from the same image. The holes are **not inherent to the decoder or the input** — they are introduced somewhere in our pipeline.

All remesh attempts (CPU SDF + MC, CPU SDF + DC, cumesh Metal UDF DC) failed because they are trying to fix a broken mesh downstream, when the breakage may originate upstream in our mesh extraction or decoder pipeline.

## Evidence Chain

### 1. The official pipeline produces good output from this image

The operator has seen coherent, hole-free TRELLIS.2 output from the T.png demo image. This is one of the official demo assets. The model is capable of producing clean geometry for this input.

### 2. Our raw mesh has massive topology defects

| Metric | Our raw mesh (trellis2mlx) |
|--------|----:|
| Boundary loops (holes) | 5,652 |
| Non-manifold edges | 300,026 |
| Boundary edges | 236,877 |
| Connected components | 496 |

### 3. The checkpoint was generated by our pipeline, not the official one

The "official control" checkpoint at `kaminos-trellis-official-control-20260628T2241Z` was generated by `trellis2mlx/generate.py`, not by the official TRELLIS.2 `Trellis2ImageTo3DPipeline`. We do not have a raw mesh from the official pipeline for comparison.

### 4. Six remesh approaches all failed

| Approach | Result |
|----------|--------|
| CPU MC, 128^3, winding number sign | Fills holes (1,602→4) but asymmetric blobs |
| CPU MC, 256^3, pseudonormal sign | 46% sign disagreement |
| CPU MC, 256^3, local normal sign | 47.5% sign disagreement, 61K non-manifold |
| CPU DC, 256^3, winding number sign | Same blobs as MC |
| cumesh Metal UDF DC, 512^3, no projection | Wireframe/lattice — meshes edges, not surfaces |
| cumesh Metal UDF DC, 512^3, projection=0.9 | Lattice with holes |

All approaches fail because the input mesh has too many holes for any sign computation (winding number, pseudonormal, local normal) to work, and UDF-based approaches extract the band boundary which forms tubes around a holey mesh.

### 5. Pre-simplification makes sign errors worse but is not the root cause

SDF divergence diagnostic showed pre-simplification causes 16% near-surface sign errors, but computing SDF on the full cleaned mesh (3M faces) still produces blobs. The underlying mesh topology is too broken for any global sign computation.

## Reframed Hypothesis

The holes are likely introduced by our mesh extraction (`trellmlx/mesh_extract.py`), which is a numpy reimplementation of the official C++/CUDA `o_voxel.convert` flexible dual grid algorithm. Possible sources:

1. **Edge intersection flag handling** — our threshold (`feats[:, 3:6] > 0`) may differ from the official implementation
2. **Quad split weight computation** — our softplus + split logic may produce different triangulations
3. **Coordinate handling** — spatial hash, neighbor lookup, or grid-to-world mapping differences
4. **Numerical precision** — float32 vs float64, numpy vs CUDA rounding

## Precise Next Steps

### Step 1: Generate official raw mesh for comparison

Run the official TRELLIS.2 pipeline on T.png through GPU Greenroom to produce a raw mesh checkpoint at the same stage. Compare topology metrics (boundary loops, non-manifold edges, components) against our raw mesh. This determines whether the holes come from extraction or upstream.

### Step 2: If extraction is the source — diff our mesh_extract.py against o_voxel.convert

Read the official C++ extraction (`o-voxel/src/convert/`) line by line against our numpy implementation. Focus on edge intersection detection, quad formation, and vertex positioning. A single threshold or rounding difference could produce thousands of missing quads (= holes).

### Step 3: If extraction matches — investigate upstream

Compare decoder outputs (7-channel features, coordinates) between our pipeline and the official at the same seed/image. The flow sampling, coordinate requantization, or decoder forward pass may differ.

### Step 4: Once extraction is fixed, remesh becomes optional

If our extraction produces the same clean mesh as the official pipeline, the cumesh Metal UDF DC remesh path is available for further topology improvement (20s at 512^3 on Metal, working infrastructure).
